# 暖账0.2.2 计划外支出与代管分摊

- 记支出时选择“计入计划”或“计划外”。计划外不计预算、分类预留和计划日均，仍计自然月个人消费。实际账户资金减少，资金不足仍可能降低首页可花金额；计划预算剩余可在计划详情查看。
- 支出可指定付款账户中的一笔代管款，并手填承担金额。实际付款90、代管承担30时，账户减90、代管减30、个人消费与计划支出为60；不抵扣表示临时垫用，仍须补回。作废同时撤销资金、代管分摊与计划统计。
- 流水显示实际付款，详情与CSV记录个人消费、代管承担、是否计入计划。没有关联计划的固定开支付款自动归为计划外。
- 写入schema4，兼容schema1/2/3；旧流水保持原有统计，不猜测历史房租归属。升级前导出完整备份，新备份不要导回旧版。

## 旧版收入与余额更新

- 收入表单可选择“不加入，只增加账户余额”或“加入当前计划的可花额度”。默认不加入；没有当前执行计划时只能不加入。这里的“加入”用于记录他人分摊：它补回已经记入计划的支出金额，不增加计划原始预算。例如计划还剩400元、支付90元后收到他人分摊30元，计划恢复为430元，实际个人负担为60元。
- 代管账户允许暂时垫付：账户实存不能低于0，但个人可用余额可以为负。例如微信实存600元全部属于代管款时，可以正常记录600元消费；个人可用显示-600，代管余额仍单独保留，之后收入或转账补回即可。
- 当前计划沿用覆盖今天、跨度最大的执行中计划。补录日期必须在该计划范围内，才能加入。
- 加入收入作为独立补回额度，不改原始预算；它抵消对应计划已发生支出的个人负担，只有对应计划增加可花空间，不同时累加给重叠计划。
- 所有普通收入都增加账户余额和个人资产。选择不加入不会增加预算上限；若之前是现金不足，到账仍可能释放原预算内的可花额度。可花金额始终取预算和个人资金限制的较小值。
- 首页、账户、计划和账本均从最新账本重新计算。收入详情显示本笔入账后的账户/个人/计划金额，以及当前金额；历史快照与当前金额分别标注。
- 作废收入自动撤回对应额度和余额；若后续资金依赖该收入则拒绝作废。旧流水不回填或猜测历史余额。
- 兼容schema1/2，写入schema3。先导出旧版完整备份，再覆盖安装。

# 暖账 0.2.0 升级说明

## 新增与调整

- 代管：账户 → 代管，登记所有人、存放账户、存入与分次归还；账户实存包含代管，个人可用和总资产扣除代管。个人消费、借出和转账不能动用代管余额。
- 首页：当前计划还可花金额；全局自动采用覆盖今天且跨度最大的执行中计划。多个计划并行，预算不相加；独立计划详情保留。
- 计划：短期7天、中期30天、长期3个月，支持自定日期和类型；执行中、下一个、计划中、已完成四状态，手动切换；“下一个”唯一。状态不会到日自动改变，执行中但未来/过期的计划不参与全局。
- 删除计划：保留账目流水，解除固定开支关联，删除预算与预留。
- 列表：计划和账本按月/年过滤，每页6项；账户按账户/应收/代管分页，余额显示当前值，历史月份和年度通过账户流水回顾查看。
- 三级分类：餐饮、交通、住房、购物、学习、娱乐、健康、通讯、人情、家庭、收入、其他；逐级选取和跨层搜索。原有自定义分类保留，设置 → 分类管理 → 补充内置三级分类可添加默认目录。新增分类用“一级/二级/三级”格式；最多三级。
- 消费趋势：年/月/日切换；柱状或折线；点击日期/月份进入流水。
- 个人统计：顶部头像进入；自然月/年统计总支出、收入、净支出（支出减收入）、结余、日均、消费笔数、最大单笔、上期变化和主要分类；逐月报表每页3个月。
- 固定开支：首页或计划页进入；设置金额、付款日、生效月份和所属计划，按到期日预留；确认支付才记支出，阻止同月重复付款，可停用和修改。付款归入实际日期的个人统计；在计划内按所属计划统计。
- 账本：全部、收入、支出、转账、作废、其他筛选；代管和借还归“其他”。
- 保留五主题和离线数据；合入此前横屏键盘修复。

# 暖账 · 安卓离线个人账本

默认使用最初的温暖米白风格。可在设置 → 更换主题中选择温暖日常、缤纷奶油、晴空蓝、静谧夜间、液晶手账五种外观。主题覆盖主页面、卡片、图表、表单与弹窗，自动保存并随完整备份恢复；旧版备份默认采用温暖日常。液晶主题使用等宽文字与墨绿预算屏，未内置预览中的七段数字字体。全部账目保存在手机本地，不需要账号，不访问网络。应用名暂定“暖账”，可在打包脚本中更改。

**0.2.0 为升级版源码，继续使用 GitHub Actions 打包 APK；本轮本地运行了 Flutter 静态分析和测试，尚未构建安卓 APK 或完成真机验收。**

本轮已精修字体、表单、卡片、预留项目和主题选择，并精简常驻说明。更新已有仓库及验证状态见 [UI_REFINEMENT.md](UI_REFINEMENT.md)。中文与数字字体随 APK 内置，详见 `assets/fonts` 中的授权说明。

## 已实现到源码的功能

- 每日花费规划：首页与计划页展示剩余日均、固定保留的初始日均、剩余天数和今日全部支出。先添加各项预算内预留，再启用每日规划；例如1000元减200元预留，30天初始日均26.66元（向下取到分）。剩余日均按剩余预算除以含今天的剩余天数实时重算，是剩余周期平均参考，不是当天额外可花额度。尚未开始按完整周期算，结束后显示0；超支保留负数缺口。日均按预算算，资金不足另行提示。
- 预留项目可增删改，专用分类可自动创建，各自显示已花、剩余和超支；点购物按钮直接记录该项目支出。每个分类每个计划只能关联一项，周期内已有同分类支出也会计入。额度内消费不重复扣减日常预算，超过预留的部分占用日常预算；原日均在首次启用时保存，调整后保留并写历史。旧备份恢复后可自行启用。
- 动态账户：新增、改名、上移/下移排序、归档/恢复；期初余额与余额核对保留记录，归档余额仍计入资产。
- 快捷记录支出、收入、账户转账；备注、日期、相册图片；错账可作废并重记，不抹除原记录。
- 总资产、当前可用、暂不可用、计划内可花；资产分布、近7日消费图、按计划消费分类统计。
- 朋友借款按人汇总、逐笔留痕、分次还款；按人还款默认抵最早登记的借款，也可指定某笔。
- 奖学金、押金与其他应收，自定义新增类型；分次到账、延期、调整余额、取消或扣损，变更原因保留。
- 自选周期，可同时保留多个计划；总预算、分类额度、分类之间挪额度、必要开支与储蓄预留。
- 同时显示起点快照、原定目标、当前目标与差额；计划调整记录保留前后值和原因。
- 可搜索流水、按日期查看；动态分类新增、改名、停用；改名同步记录与当前分类额度。
- 本地完整备份/恢复（含图片）及 CSV 导出，均由用户手动发起。没有自动上传或云同步。
- 预算、分类额度或资金底线突破时，在操作后提醒。系统通知需要自行开启和授权，没有每日记账或到账提醒。

## 第一次云端打包：只用电脑浏览器

1. 在 GitHub 建立一个 **Private（私有）仓库**，例如 `warm-ledger`。
2. 解压项目，进入看到 `pubspec.yaml`、`lib`、`tools`、`test`、`.github` 的那一层。
3. 在仓库中选择 **Add file → Upload files**。把这一层的所有内容上传并提交，包含 `.github` 文件夹。不要把外层 `warm_ledger` 文件夹整层套进去；仓库根目录必须直接看到 `pubspec.yaml`。
4. 打开 **Actions → Build Android APK → Run workflow**。首次打包勾选 `first_build`，然后运行。
5. 流程会生成 Android 工程、检查代码、运行资金规则测试、生成签名并编译 APK。任何检查失败都会停止，不会上传“成功”的 APK。
6. 成功后在本次运行底部 **Artifacts** 下载 `warm-ledger-apk`，解压获得 `app-release.apk`，传到手机安装。安装来源授权只授予用于打开安装包的文件管理器/浏览器。
7. **同时下载 `warm-ledger-signing-backup-KEEP-PRIVATE`**，妥善保管解压得到的 `signing-secrets.json`。这是后续覆盖更新所需的私有签名，不要上传到仓库或发给别人。

### 后续更新：沿用同一签名

在仓库 **Settings → Secrets and variables → Actions → New repository secret** 添加两个秘密：

| 名称 | 内容 |
|---|---|
| `WARM_KEYSTORE_B64` | 签名备份中同名字段的完整值，不带双引号 |
| `WARM_STOREPASS` | 签名备份中同名字段的完整值，不带双引号 |

以后上传修改后的代码，再运行 workflow，**不勾选 `first_build`**。每次构建使用递增版本号和相同签名，支持覆盖更新。没有保存签名时，流程默认拒绝重新生成，避免误以为可以直接覆盖已有安装。签名丢失会影响更新；卸载前务必导出完整账目备份。

Actions 的两个下载包保留14天，下载后保存在你自己的安全位置。云端处理的只有代码和打包签名，手机账目不会自动传到 GitHub。

## 资金计算规则

- 金额全部用整数“分”保存，避免浮点误差。
- 总资产＝所有账户余额＋未收回借款＋押金＋预计到账款。这里遵循用户偏好，把预计到账纳入总资产，但单独标注不可立即使用。
- 借出/付押金：账户减少、应收增加，总资产不变；归还/到账：反向变化，总资产不再增加一次。
- 直接收入和实际消费单独统计。应收新增、收回不记为普通收入；因此普通收入统计并非完整的银行现金流入统计。
- 每个计划独立测算，不把多个重叠计划的预留重复相加。选择哪个计划，首页就展示哪个计划的可花额。
- 必要支出预留按分类匹配实际消费；同一计划每分类只允许一个预留。建议房租等使用专门分类。
- 预算外预留的消费在预留额度内不占用普通消费预算，超出预留的部分占用预算；预算内预留则扣留尚未支付的必要开支，避免重复扣钱。
- 可花额＝`max(0, min(可用余额－必要支出剩余预留－储蓄预留, 总预算－预算内已花－预算内必要支出剩余预留))`。
- 资产底线、可用底线是提醒线，不额外从可花额扣一次，避免与储蓄预留重复冻结。
- 起点在建立计划时由用户确认并固定，默认填当前总资产与可用余额；回顾过去周期时，可以手动填写当时真实的起点。之后补账、改日期或作废流水不静默覆盖原起点，可新建修正计划。
- 预算/底线可以突破，不阻止正常记账；账户实际余额不允许记为负数。本版按没有信用账户和欠债的使用场景设计。

## 数据与版本边界

- 从空账本开始，分类提供可编辑的初始列表，没有预置账户、假流水或固定预算。
- Android 6.0（API23）及以上。图片从系统相册选取，单张压缩后最大2MB。
- 数据写入 SQLite 事务；资金操作先在副本验证，成功保存后才更新界面，保存失败不提交半笔账。
- 应收名称/到期日变更保留在日志中；作废资金流水不会自动撤销元数据更名。原定计划快照始终保留。
- 完整备份是未加密 JSON，含图片；CSV 只能分析流水，不能恢复完整账本。导入前先备份当前数据；导入经过基本结构和引用检查后还需确认替换。
- 本版完整备份导入上限64MB，适合个人账本；图片较多时须控制附件数量。没有后台余额读取和后台定时监控，系统通知只在使用 App 的操作后触发。
- 无网络权限；关闭 Android 自动备份，手动备份文件由用户选择位置。若用户自行选择网盘目录保存文件，属于用户主动操作。
- 尚无自动账单导入、跨设备同步、桌面小组件、生物识别锁、账户拖动排序和完整月历网格；账本已经提供按日期筛选。

- `test/editor_test.dart`、`test/ui_review_test.dart`：录入交互、键盘、字体缩放、各主题页面布局与截图导出。

- `.github/workflows/build-apk.yml`：固定 Flutter 3.35.7 / Java17，分析、测试和云端打包。
